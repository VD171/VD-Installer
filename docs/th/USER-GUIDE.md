## 1. VDInstaller คืออะไร

VDInstaller เป็น **โมดูล WebUI** ของ KernelSU / APatch / Magisk ที่ติดตั้งไฟล์ APK แบบ sideload ในฐานะ
root โดยไม่มีสิ่งขัดขวาง: ไม่มีกล่อง "grant su" ไม่ต้องใช้เทอร์มินัล และไม่ต้องสู้กับตัวตรวจสอบของ Play
Protect รองรับทั้ง APK เดี่ยว ทั้งโฟลเดอร์ในครั้งเดียว และแอปแบบแยกไฟล์ (`.xapk` / `.apkm` / `.apks` /
`.zip` หรือไฟล์แยกที่กระจัดกระจาย) และยังสามารถแสดงแหล่งติดตั้งว่าเป็น Play Store เพื่อให้แอปไม่ดูเหมือน
ถูก sideload

## 2. ความต้องการของระบบ

- Android 8.0 ขึ้นไป (API 26+)
- โซลูชัน root ที่รองรับ WebUI: **KernelSU**, **APatch** หรือ **Magisk**

## 3. การติดตั้งและการเรียกใช้ครั้งแรก

1. ดาวน์โหลด `VD-Installer-vX.XX-universal.zip` ล่าสุดจากหน้า
   [Releases](https://github.com/VD171/VD-Installer/releases)
2. แฟลชเป็นโมดูลในตัวจัดการ root ของคุณ (*Modules -> Install from storage*)
3. VDInstaller เปิดใช้งาน **โดยไม่ต้องรีบูต** - เป็นแบบในตัว (WebUI + ไบนารีที่มาพร้อม) จึงไม่มีอะไรต้อง
   เมานต์
4. เปิด WebUI ของ **VDInstaller** จากรายการโมดูลในตัวจัดการ root ของคุณ

เมื่อแฟลช ตัวติดตั้งจะเก็บเฉพาะ ABI ของอุปกรณ์คุณ และรันด่านตรวจความถูกต้อง `.sha256` ที่บังคับ ซึ่งจะ
**ยกเลิก** หากไฟล์ zip เสียหายหรือถูกตัดทอน การตั้งค่าถูกเก็บไว้ที่ `/data/adb/vdinstaller` และคงอยู่ข้าม
การอัปเดต

## 4. แนะนำ WebUI

สามแท็บ:

- **Install** - เลือกโหมด เลือก APK หรือโฟลเดอร์ ติดตั้ง และดูความคืบหน้าแบบสด
- **Options** - แหล่งติดตั้ง สวิตช์ตัวตรวจสอบของ Play Protect และแฟล็กการติดตั้ง ทุกอย่างถูกบันทึกโดย
  อัตโนมัติ
- **About** - เวอร์ชัน สิ่งที่มันทำ ความต้องการ ลิงก์ และสัญญาอนุญาต

## 5. การติดตั้ง APK

คุณเลือกโหมดบนแท็บ **Install**, VDInstaller ไม่เดาเอง

| โหมด | คุณให้ | สิ่งที่เกิดขึ้น |
|---|---|---|
| **APK เดี่ยว** | ไฟล์ `.apk` | หนึ่งเซสชันติดตั้ง หนึ่งแอป |
| **โฟลเดอร์ของ APK** (batch) | โฟลเดอร์ที่มีไฟล์ `.apk` อิสระ | แต่ละ APK ถูกติดตั้งแยกกัน ทีละไฟล์; batch ที่สำเร็จบางส่วนจะรายงานว่าไฟล์ใดล้มเหลวและเพราะอะไร |
| **อาร์ไคฟ์แบบแยก** | ไฟล์ `.xapk` / `.apkm` / `.apks` / `.zip` | แตกไฟล์ จากนั้นติดตั้ง `base.apk` + splits เป็นแอปเดียวในเซสชันเดียว (วางไฟล์ XAPK OBB ด้วยหากมี) |
| **โฟลเดอร์แบบแยก** | โฟลเดอร์ที่มีไฟล์ `.apk` แยกที่กระจัดกระจายของแอปเดียว | splits ถูกติดตั้งเป็นแอปเดียวในเซสชันเดียว |

แอป "แบบแยก" คือ APK หนึ่งที่ถูกแบ่งเป็นฐานบวกกับ config APK ตามความหนาแน่น / ตาม ABI / ตามภาษา, มัน
ต้องถูกติดตั้ง **พร้อมกัน** ในหนึ่งเซสชัน ซึ่งโหมดแบบแยกจัดการให้คุณแล้ว

### 5.1 กล่องโต้ตอบ Browse

**Browse** เปิดตัวเลือกไฟล์ที่แสดงโฟลเดอร์และไฟล์ที่ติดตั้งได้ ณ เส้นทางหนึ่ง:

- แตะ **โฟลเดอร์** เพื่อเข้าไปข้างใน, **Up** กลับไปยังโฟลเดอร์แม่
- ในโหมดไฟล์ (APK เดี่ยว / อาร์ไคฟ์แบบแยก) แตะ **ไฟล์** เพื่อเลือก
- ในโหมดโฟลเดอร์ (โฟลเดอร์ของ APK / โฟลเดอร์แบบแยก) ให้เข้าไปในโฟลเดอร์แล้วแตะ **Use this folder**

คุณยังสามารถพิมพ์หรือวางเส้นทางโดยตรงได้ (เช่น `/sdcard/Download/app.apk`)

### 5.2 ความคืบหน้า การยกเลิก การกลับมาทำต่อ

การติดตั้งทำงานเป็น **กระบวนการ root ที่แยกตัว** การ์ดความคืบหน้าจะแสดงเฟส, **Cancel** หยุดมัน หากคุณ
ปิด WebUI กลางคันระหว่างติดตั้ง การติดตั้งจะดำเนินต่อไป และ UI จะเชื่อมต่อกลับด้วยหมายเลขปฏิบัติการเมื่อ
คุณเปิดมันอีกครั้ง

## 6. ตัวเลือก

ทุกอย่างที่นี่ถูกบันทึกโดยอัตโนมัติและมีผลกับการติดตั้งครั้งถัดไป

### 6.1 แหล่งติดตั้ง

แอปที่เพิ่ง sideload จะประกาศต่อทุกแอปที่อ่านมัน (และต่อการพิสูจน์ตัวตน) ว่ามันถูก sideload VDInstaller
สามารถแสดงแหล่งเป็น Play Store แทนได้

- **แสดง Play Store เป็นตัวติดตั้ง** (เปิดโดยค่าเริ่มต้น) - ตั้ง `installerPackageName` ผ่าน
  `pm install-create -i com.android.vending` มีผลทันที
- **ปลอมแปลงตัวริเริ่มด้วย** (เปิดโดยค่าเริ่มต้น) - ตั้ง `installInitiator` และ `packageSource` โดยแก้ไข
  `/data/system/packages.xml` สิ่งนี้ **รู้จัก ABX** (ถอดรหัส -> แก้ไข -> เข้ารหัสใหม่ พร้อมสำรองแบบ
  ตรงไบต์และการสลับแบบอะตอม) และมีผล **หลังการรีบูตครั้งถัดไป** เพราะตัวจัดการแพ็กเกจแคช
  `packages.xml` ไว้

### 6.2 ตัวตรวจสอบแพ็กเกจของ Play Protect

การติดตั้งแบบ sideload อาจถูกปฏิเสธด้วย `INSTALL_FAILED_VERIFICATION_FAILURE` โดยตัวตรวจสอบแพ็กเกจ
ของ Play Protect เป็นสวิตช์แบบ 3 ทาง:

- **คงไว้ตามเดิม** (ค่าเริ่มต้น) - ปิดเฉพาะช่วงการติดตั้ง แล้วคืนกลับสู่สถานะเดิม **ที่เป๊ะ** (ลบอีกครั้งหาก
  ไม่เคยมีค่าชัดเจน เพราะค่า `0`/`1` ตรงที่เคยไม่มีค่า เป็นร่องรอยในตัวมันเองบนอุปกรณ์แบบ stealth)
- **เปิดเสมอ** - บังคับเปิดและคงไว้
- **ปิดเสมอ** - บังคับปิดและคงไว้ WebUI เตือนว่า การปล่อยให้ปิดไว้คือร่องรอยแบบ stealth และปิดการสแกน
  มัลแวร์สำหรับทุกการติดตั้ง

### 6.3 Developer Verification

Developer Verification ปี 2026 ของ Android บล็อกการติดตั้งแอปจากนักพัฒนาที่ไม่ได้ลงทะเบียนบนอุปกรณ์ที่
ได้รับการรับรอง แต่มันบังคับใช้โดย **บริการแยกต่างหาก** ไม่ใช่ Play Protect และการติดตั้งแบบ root
**ได้รับการยกเว้นอยู่แล้ว** จากมัน (ข้อยกเว้นเดียวกับที่การติดตั้งผ่าน ADB ได้รับ) VDInstaller ติดตั้ง APK
ของคุณไม่ว่ากรณีใด ดังนั้นสวิตช์นี้จึงเป็นแบบ **พยายามอย่างดีที่สุดและซื่อสัตย์**: มันใช้ปุ่มจริงเฉพาะเมื่อมี
ปุ่มนั้นอยู่ และไม่เคยแสร้งว่าพลิกสวิตช์ที่ไม่ทำอะไรเลย

### 6.4 แฟล็กการติดตั้ง

| แฟล็ก | ผลลัพธ์ |
|---|---|
| **มอบสิทธิ์รันไทม์ทั้งหมด** | มอบทุกสิทธิ์รันไทม์ตอนติดตั้ง (`-g`) |
| **อนุญาตแพ็กเกจทดสอบ** | ติดตั้งแพ็กเกจที่ระบุว่าใช้ทดสอบเท่านั้น (`-t`) |
| **ข้ามการบล็อก target SDK ต่ำ** | ติดตั้งแอปที่มี `targetSdk` เก่ามาก |
| **ผู้ใช้เป้าหมาย** | หมายเลขผู้ใช้ Android ที่จะติดตั้งให้ (ค่าเริ่มต้น `0`) |

### 6.5 การซ่อนตัว

เพื่อการ stealth ควรพิจารณาซ่อนตัวจัดการ root และแอปที่อ่อนไหวของคุณด้วย HMA-OSS VDInstaller **ไม่เคย
แตะต้องการตั้งค่า HMA-OSS ของคุณ** - คำแนะนำนี้เป็นเพียงการเตือนความจำ, คุณต้องทำการเปลี่ยนแปลงเองใน
HMA-OSS

## 7. การสั่งงาน VDInstaller จากผู้ช่วย AI

เอนจินพูดภาษาสัญญา JSON เล็ก ๆ ผ่าน `scripts/helper.sh` ดังนั้นเอเจนต์จึงสามารถสั่งงานทุกการกระทำที่
WebUI ทำได้ ดูที่ [AI-AGENTS](AI-AGENTS) สั่งงานผ่านสัญญา อย่าขูดข้อมูลจาก WebUI

## 8. การแก้ปัญหาและคำถามที่พบบ่อย

**ฉันได้ `INSTALL_FAILED_VERIFICATION_FAILURE`** นั่นคือตัวตรวจสอบแพ็กเกจของ Play Protect เมื่อสวิตช์ตัว
ตรวจสอบอยู่ที่ **คงไว้ตามเดิม** (ค่าเริ่มต้น) VDInstaller จะปิดมันในช่วงการติดตั้งแล้วคืนกลับ มันจึงไม่เกิดขึ้น

**ฉันเปิดแหล่ง Play Store แล้ว แต่แอปยังดูเหมือนถูก sideload** ส่วนของตัวติดตั้งมีผลทันที, ส่วนของตัวริเริ่ม
(`packages.xml`) มีผล **หลังการรีบูตครั้งถัดไป**

**มันข้าม Developer Verification ของ Google หรือไม่** ไม่จำเป็นต้องข้าม - การติดตั้งแบบ root ได้รับการยกเว้น
(ดู 6.3) ไม่มีสวิตช์ปลอมสำหรับมัน

**ต้องรีบูตหรือไม่** ไม่ ยกเว้นการปลอมแปลงตัวริเริ่มที่เป็นตัวเลือก

**การถอนการติดตั้ง VDInstaller จะลบแอปที่ฉันติดตั้งไปหรือไม่** ไม่ - แอปเหล่านั้นเป็นการติดตั้งจริงที่ระบบเป็น
เจ้าของ, การลบโมดูลเพียงแค่เก็บกวาดสถานะของ VDInstaller เอง

**ปลอดภัยหรือไม่** มันติดตั้ง APK ที่คุณเลือก และเมื่อปิดตัวตรวจสอบ จะข้ามการสแกนมัลแวร์ - ติดตั้งเฉพาะ APK
ที่คุณไว้วางใจ มันไม่เคยลดทอนสิ่งใดอย่างเงียบ ๆ
